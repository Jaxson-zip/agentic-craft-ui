# 艺术方向与动效

用于用户明确追求独特风格、品牌体验、创意原型或叙事动效的任务。它补充 UI 参考的可读性、状态和可访问性要求，不给普通表单与已有产品强加重设计流程。

## 把概念做成视觉语言

在已有品牌与需求内，写出简短的方向说明：产品核心对象、希望产生的感受、适合的表现媒介，以及主操作怎样与这个对象关联。例：整理思绪可用可聚合的对象表达关系；旅行叙事可用路线和沿途片段组织阅读。概念须符合实际功能，不把隐喻包装成尚未实现的能力。

把方向落实到下面的选择。只有配色或圆角变化，不算不同的艺术方向。

| 选择 | 需要说明与做出的结果 |
| --- | --- |
| 构图与阅读节奏 | 首屏焦点、标题与主操作的位置、图文关系；后续章节怎样改变密度与节奏 |
| 字体与语言 | 展示字与任务正文的职责、标题断行与混排；核对实际加载和中文回退 |
| 图像与材质 | 插画、摄影、几何、纸张、像素或其他媒介的一致语法；确定资产来源与实现方式 |
| 核心对象与交互 | 用户操作什么对象，动作怎样表达整理、探索、连接或完成，并对应真实状态 |
| 动态节奏 | 哪个动作值得强调、哪些元素陪衬；入场、操作与结果之间怎样连续 |

方向尚不明确且对结果影响较大时，做少量可比较的具体构图或交互片段。让方案在视觉焦点、媒介与操作方式上有实质差异；按已有授权继续推进，不固定要求三套完整网站或逐轮审批。

用户已要求比较的方案数与节奏保持为验收条件，方向选择前只扩展必要的代表片段。被否定的视觉不能默认为可继续精修的已选方向。底层复用选择与艺术方向分开：复用组件行为/动画能力后仍需设计排版、色彩角色及动作语义；不用自写整套控件来证明原创。

## 用参考提取方法

优先检查作者的实际作品、演示或美术说明。记录来源、观察范围和具体可迁移的方法，例如标题如何与插画共同形成焦点、对象移动如何解释状态。获奖、流行或技术复杂度都不能自动证明界面优秀。

把作者自述的奖项、机构记录与设计判断分开；活动品牌设计不能标成参赛获奖作品。静态截图只能评价渲染，文字介绍只能支持概念分析，动效质量需要实际播放或操作。设计文档中的计划与当前实现可能不同，以实际观察标注差异。

提取构图关系、媒介一致性和交互语义，再为当前产品创作。不要拼贴其他作品的标志、人物、完整构图或未经许可的资产；字体、图片和音频确认授权。参考不固定为某个赛事、网站或深色风格库，也不把每次小修复变成全网调研。

## 让排版参与表达

先用真实标题、正文和主行动完成构图。展示标题可使用有性格的字体、大字阶、特殊断行或非对称关系；任务正文保持舒适阅读，不能让整页都变成海报字。字体没有加载或 CJK 回退改变字面时，重新检查断行与几何。

需要章节叙事时，用图文比例、留白、密度与场景变化形成节奏；不要连续复制相同尺寸的卡片区块。主视觉、标题与按钮避免争抢同一焦点。缩到窄屏后重新组织阅读顺序，而不是等比缩小桌面舞台。

标志性图像可能比更多 CSS 装饰更有效。按方向选择已有可用资产、原创 SVG、合适的生成图像或其他媒介；不默认必须用 3D、shader、视频或外部生成服务。资产暂缺时说明占位范围，别用占位图的精致程度宣称最终质量。

## 把动效写成状态变化

先决定需要表达的变化，再选技术。区分功能反馈、空间转换、叙事表达和环境氛围，让核心动作有明确起止；环境动画的强度低于阅读和操作。一个有意义的主动作可以建立记忆点，不要求每个控件都动。

为关键动态片段写一份简短说明，至少能回答：

| 项目 | 要回答的问题 |
| --- | --- |
| 触发与含义 | 用户做什么或什么状态发生变化？动画帮助理解什么？ |
| 对象与连续性 | 谁从哪里到哪里？选择对象、标题与结果怎样保持关联？ |
| 节奏与结束 | 时长、缓动、先后关系如何适合内容与操作频率？结束后稳定在哪个状态？ |
| 中断与降级 | 连续点击、退出、失败和减少动态效果时如何显示准确结果？ |

例如选择故事章节时，可以让选择对象、配图、标题和开始按钮共同转向新章节；更新中的片段要表达过渡，不能混合旧标题与新按钮而造成误操作。删除、付款或保存的视觉完成必须服从真实结果，不能因动画结束就宣称成功。

优先复用项目设施与平台能力。CSS 适合简单反馈；复杂编排、滚动关联或物理表现有明确需要时再选库。变换与透明度可优先考虑，但仍测实际帧表现；限制持续粒子、模糊、巨大图像与并行动画，离屏或后台无必要时停止。Canvas/3D 中的主操作要有可访问的 DOM 入口。

尊重 `prefers-reduced-motion`：用即时结果、稳定画面或适当的低动态替代表达，不能留下瞬间大幅位移。保持对象身份、结果与关键文案；有持续动态或音频时提供适合的停止方式，避免关键任务依赖自动播放。

## 检查是否成立

实际看首次进入、一次主操作、结果稳定和必要的恢复路径；检查阅读是否被运动打断、对象是否连续、反复操作是否拖沓。检查键盘、窄屏与减少动态效果，按范围记录流畅度及具体设备限制。

倾斜、叠放和裁切构图要检查真实文字区域与操作热区，而不只量页面是否溢出；装饰边缘可叠放，必要内容和行动不能因此被遮住。对象转换比对前、中、后三个时刻的颜色、字形、断行、角度和尺寸，避免主对象突然换成另一套通用素材。窄屏可以改变排布来保留阅读与操作，不必缩小或照搬桌面叠放。

视觉复核时分别判断：概念是否进入了构图与操作；字体、素材和运动是否属于同一套语言；是否有能解释产品的记忆点；真实长内容与异常状态是否仍成立。发现只有漂亮首屏、内容区退回通用模板时，优先修表达的一致性。

工作型 SaaS 的质感还要落在对象与任务环境上：项目/周期上下文、重要属性的层级、可持续使用的密度、导航与详情的连续操作。比较片段的模拟内容应代表业务，不能只用“安装组件、字体、构建通过”等实施事项填满界面。用户反馈普通或缺乏精致感时，定位具体的构图、内容和控件缺口；加运动或更换配色不能替代这些检查。

精修时先审查关系，再调参数：标题、正文、元信息和行动的层级是否稳定；文字基线、图标与控件是否视觉对齐；区块留白是否体现分组；强调色是否集中在当前选择、关键行动与业务状态。用正常/长内容和聚焦/选中状态检查这些关系，不用统一减字号、加阴影或增大圆角来制造“高级感”。实际加载的中英文字体、字重与行高应进入检查，源码写了字体名不证明呈现正确。

多页面产品选择一组相连的代表场景检查，例如列表 → 详情 → 编辑反馈，再看实际存在的设置或审计页。共享导航、字阶、字段标签、密度和状态色应延续同一语言；页面可按任务改变布局，不强制同一个卡片模板。窄屏重排后仍要核对上下文、属性与返回路径。只精修过一个页面时明确其覆盖范围，不据此宣称整个设计系统成熟。

保留能审阅的预览和关键状态证据；动效用可运行页面、录屏或实际操作记录证明，截图只能证明某一帧。明确哪些判断来自浏览器观察、源码或作者说明；构建与单元测试通过不能证明艺术方向已被用户认可。
