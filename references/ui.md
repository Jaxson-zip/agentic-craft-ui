## 1. 从主题出发，先写设计计划

好看的界面来自**这个产品自己的世界**：它管理什么东西、给谁用、在什么场景下打开。给 8–11 岁女孩的玩具和给财务分析师的报表，配色、字体和密度应该完全不同。需求没说清主题时，先自己提出一个具体的主题、用户和主要任务，写进计划。

动手写代码前，先写一份简短的设计计划：

- **颜色**：4–6 个具名的十六进制颜色，例如“纸白 #FBFAF7、墨黑 #1F1D1A、苔绿 #4F7A5B”，并说明每个颜色从主题里哪里来。
- **字体**：用哪一两套字体、各自负责什么（见第 4 节）。
- **布局**：一句话说明，再画一个 ASCII 线框；写清内容左对齐还是居中。
- **记忆点**：整页只有一个最值得记住的地方，其余保持安静。

示例（一个记录读书摘抄的小工具）：

```text
主题：读书人的摘抄本，安静、像纸
颜色：纸白 #FBFAF7（底）、墨黑 #1F1D1A（字）、旧书脊红 #A1462E（书名和选中）、铅灰 #8A857D（辅助）、浅米 #F1EDE4（卡片）
字体：MiSans 做界面，书摘正文用思源宋体
布局：左侧按书分组的书架，右侧一列摘抄卡片，最宽 680px，左对齐
┌────────┬──────────────────────┐
│ 书架    │ 《置身事内》 · 12 条  │
│ 置身事内 │ ┌──────────────────┐ │
│ 原则    │ │ 摘抄正文（宋体）    │ │
│ …      │ └──────────────────┘ │
└────────┴──────────────────────┘
记忆点：每条摘抄左边有一道书脊红的竖线，像夹在书里的书签
```

写完先对照下一节审一遍，再开始写代码。

## 2. AI 痕迹：计划和成品都要对照

下面这些是 AI 生成界面最常见的“默认值”。它们在某些项目里是对的，但不论主题都出现时，就是一眼 AI。需求没指定的方向上，不要把自由度花在这些上：

- 暖奶油色底（#F4F1EA 附近）配衬线大标题和陶土橙强调色。
- 近黑底配单一的亮绿或朱红强调色。
- 报纸风：细线分隔、零圆角、密排多栏。
- SaaS 卡片套件：所有内容切成一样的圆角卡片，同一个圆角、同一层灰阴影，再加渐变色块当装饰。
- 模板装饰：每个标题上方一行全大写小标签；用“A · B · C”中点串起元信息；按钮文字后面加“→”；用 #111 这类“带色调的黑”代替黑。
- 标题里只把一个词换成彩色、粗体或斜体。
- 首屏一个大数字 + 小标签 + 几个统计 + 渐变点缀。
- 一排等宽统计卡片下面接一张表格，或者每行列表都做成一张带边框阴影的卡片。
- 序号标记（01 / 02 / 03），但内容其实不是先后步骤。
- 每个区块都淡入上移，每张卡片都有悬停动画。
- 紫蓝渐变当主色；emoji 当正式的功能图标。

计划里有和上面雷同的部分，改掉它，并在汇报的“设计”一行写一句改了什么。

## 3. 配色

- 从主题里取色：产品管理的东西、使用场景、材质，就是配色的来源。用 4–6 个具名颜色，其中只有一个强调色。
- 想不出来时，可以参考国内产品的做法，但要按自己的主题调整，不要照抄：滴答清单（任务）用柔和蓝 #4772FA，flomo（笔记）用薄荷绿 #30CF79，Folo（阅读）用橙 #FF5C00，Bob（翻译）用灰蓝 #5672CD。
- 强调色用在文字上时，对比度至少 4.5:1；配一个更深的文字色和一个很浅的底色一起用。
- 页面上已有大面积的平台色（比如小红书红、公众号绿）时，强调色避开相近的色相。
- 金融涨跌按中国习惯**红涨绿跌**；红色在国内也表示喜庆，所以错误状态要配文字或图标。

## 4. 中文排版与国内环境

- **字体随项目打包**：`npm install misans`（小米，可免费商用，按 `unicode-range` 分片，只下载用到的字）或 HarmonyOS Sans；长文可加思源宋体。字体栈 `"MiSans", -apple-system, "PingFang SC", "Microsoft YaHei", sans-serif`。只靠系统字体时，Windows 上是雅黑配另一套数字，看起来拼凑。
- **字号**：正文 15–16px，行高 1.6–1.75，每行不超过 40 个汉字；手机输入框至少 16px，防止 iOS 放大。
- **字重**：400 / 500 / 600。中文不用斜体（是机器拉斜的），不用负字距。
- **数字**：金额和日期用 `font-variant-numeric: tabular-nums`；写法 `¥1,234.00`、`10月24日 周六`、`3 分钟前`。
- **大陆能打开**：不用 Google Fonts、reCAPTCHA、Firebase、Google 地图；依赖用 npm 装进项目，慢就用 `registry.npmmirror.com`。地图用高德或腾讯，短信和验证码用阿里云或腾讯云。
- **手机优先**：先按 375–430px 设计，主按钮放在拇指够得到的底部；很多链接会在微信内置浏览器里打开，它不能直接下载文件。

## 5. 组件库与主题

| 场景 | 默认 |
| --- | --- |
| 网页（个人项目、AI 应用） | React + Tailwind + shadcn/ui |
| 网页（企业后台、数据密集） | Ant Design 或 Arco Design |
| 已有 Vue 项目 | Arco Design Vue 或 TDesign |
| 微信小程序 | 原生 + TDesign 小程序；要多端时用 Taro 或 uni-app |
| 手机 App | 已有 Web 栈用 uni-app 或 React Native，否则 Flutter |
| 单页小工具 | 原生 HTML/CSS/JS |

组件库只解决“好用、稳定、可访问”，不解决“好看”。**一定要用设计计划里的颜色、字体、圆角换掉默认主题**，通过组件库自己的主题机制改，不要到处写覆盖样式：

```css
/* shadcn/ui：globals.css 里的 :root */
--primary: 15 56% 41%; --radius: 0.625rem;
```

```tsx
// Ant Design
<ConfigProvider theme={{ token: { colorPrimary: '#A1462E', borderRadius: 8, fontFamily: 'MiSans, "PingFang SC", sans-serif' } }}>
```

## 6. 布局参考与防空洞

先写一句“用户打开页面最常做的事”，再看做同一件事的产品怎么排。这些是参考，按你的主题改：

| 核心动作 | 参考 |
| --- | --- |
| 管理一批条目（任务、订阅、账单） | 滴答清单：分类侧栏 + 按时间分组的列表 + 详情栏 |
| 随手记录、回顾 | flomo：侧栏放统计和标签，中间一列记录，输入框在最上面 |
| 写文档 | 思源笔记：文档树 + 编辑区 + 大纲 |
| 和 AI 对话 | LobeChat：会话列表 + 对话，回答按文章排版，输入框固定在底部 |
| 读信息流 | Folo：来源、条目、阅读三栏 |
| 个人主页、博客 | Innei：单栏居中 |
| 管理多个项目 | Dify：卡片网格，进项目后换侧栏 |

手机上：侧栏变抽屉或顶部标签，详情变新页面或底部面板。

防空洞：

- 并排两栏高度差超过一半，就改一栏，或把短的一栏固定（sticky）。
- 数据稀疏（有数据的日子不到三分之一）不画柱状图，改用短列表或时间线。
- 卡片里只有一两行字就不用大卡片。
- 阅读和列表区最宽 640–760px，多出来的宽度给侧栏或详情。

## 7. 组件：做与不做

[组件配方](../assets/patterns.html) 并排放了这些对比，可以直接打开看。

| 做 | 不做 |
| --- | --- |
| 列表扁平分组：一行 = 图标 + 标题 + 一行说明 + 右边一个数字或时间 | 每行一张带边框阴影的卡片，再塞徽章、进度条、按钮 |
| 有品牌的实体用真实 logo（`simple-icons`、`@lobehub/icons`），放在浅色底方块里 | 整页只有文字，或拿 emoji 充当功能图标 |
| 编辑、删除放进悬停菜单、右键或详情页 | 每行摆一排按钮 |
| 大数字用中等字重，旁边一句话说明它意味着什么 | 800 粗体大数字下面挤一串灰字 |
| 图表只用强调色的深浅，重点值用实色 | 深灰细柱，像默认图表库 |
| 提示条用中性浅色底 | 大块彩色底，比正文还抢眼 |
| 删除后给“撤销” | 每次都弹确认框 |
| 输入框有可见标签，错误就近提示，失败不丢输入 | 只靠 placeholder；出错清空表单 |
| 操作用 `button`，跳转用 `a`，键盘能走完主路径，焦点看得见 | 用 `div` 当按钮 |

## 8. 动效

- 回应用户操作的动效（打开、展开、确认、删除后让位）是好的：它说明了发生了什么变化。
- 不是用户触发的动效要少用。一个精心编排的时刻（一次加载序列或一次揭示）胜过到处撒效果。
- 大多数动画不超过 300ms，高频操作不加；只动 `transform` 和 `opacity`；`prefers-reduced-motion` 下关掉。

## 9. 文案

- 站在用户角度命名：用户管理的是“提醒”，不是“定时任务配置”。
- 按钮写会发生什么：“保存修改”，不写“提交”。同一个动作全程同名：按钮叫“发布”，提示就叫“已发布”。
- 出错时说清楚发生了什么、怎么解决，不道歉、不含糊；空页面告诉用户下一步做什么。
- 口语、短句，中英文之间加空格；每段文字只做一件事。

## 10. 截图自评

在桌面（1280px）和手机（375px）各截一张图，像设计师一样挑毛病，再改一轮：

- 和设计计划一致吗？有没有不知不觉滑回第 2 节的某个默认值？
- 记忆点只有一个吗？去掉一个最多余的装饰。
- 中文和数字是同一套字体吗？在 Windows 上看过吗？
- 有没有超过四分之一屏的空白？手机上有没有横向滚动、按钮压住文字？
