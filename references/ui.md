# UI 与交互

用于新产品、页面新增或明显的交互改造。老项目的小修复保留既有组件与视觉语言。

## 原型的范围

围绕用户最重要的一条完整任务路径制作可点击原型，而非堆砌所有页面。Mock 数据包含正常、长文本、缺失值和失败情况；标明模拟数据，不把 mock 演示称为真实 API 联调。昂贵或不可逆操作在原型中使用模拟结果。

把需要用户判断的布局、流程和内容展示出来。如果用户已给定设计或授权直接实现，就沿现有授权继续。需要选择时只问能改变方案的具体问题。

## 视觉决策

优先使用已有品牌与设计系统。没有既有规范时选择以下方向之一，并落到字体、字号层级、间距、色彩角色、边框、焦点和控件尺寸，不仅列风格名称。

| 方向 | 适用情况 | 实现重点 |
| --- | --- | --- |
| Apple Minimal（默认候选） | 内容与操作优先的消费产品 | 清晰层级、克制留白、柔和中性色；玻璃和大圆角按用途选择 |
| Linear Dark | 长时间使用的开发工具 | 暗色层级、可读文字、明确选中态；密度不以缩小可点击区域为代价 |
| Clean Tech | SaaS、管理后台和商业工具 | 网格、表格对齐、单一强调色、状态与操作的清晰区分 |

用户偏好、内容密度和平台特征高于默认候选。禁止为了套预设引入新 UI 或动画框架；复用项目现有方案。

## 状态与操作

对相关页面或组件说明 loading、empty、error、success：

- Loading：等待反馈，避免可重复提交造成重复副作用。
- Empty：解释尚无内容的原因，提供有意义的下一步。
- Error：保留可恢复输入；说明失败位置，提供重试或返回路径。
- Success：结果、状态和下一步一致；更新真实数据后再显示完成。

同时覆盖必要的禁用、校验、权限不足与长内容状态。状态仅在业务需要时增加，不做无关演示。

## 交互检查

检查窄屏和宽屏、内容溢出、触摸目标、键盘导航、可见焦点、表单标签和状态提示。支持减少动态效果的用户设置；动画服务于状态变化，不掩盖等待或错误。

有浏览器工具时实际走通相关路径并检查控制台。没有时运行可用的组件/交互测试，明确视觉部分未验证，不能把阅读代码当成视觉验收。

原型切换真实数据时，沿现有数据访问边界替换 mock，验证字段、错误与异步状态；不要只拔掉 mock 后用接口 200 宣称 UI 已完成。
