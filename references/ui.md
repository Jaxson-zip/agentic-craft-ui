# UI 与交互规范

本指南用于指导新功能设计、界面重构与原型落地。已有项目保留既有设计系统；无既有系统时，依据用户、任务与平台推导成熟、明净的商业软件表达，根除模板感与业余感。

## 风格与配色前置确认铁门禁（终结盲猜与纯抽卡）

界面视觉风格与调色板是直接决定软件商业质感的核心决策。**严禁 Agent 在新界面中私自盲猜调色板或凭空发挥（坚决杜绝“一言难尽”的泥黄、怪异配色、发灰油垢感与学生作坊感）**。

按以下三态执行决策与问询：
1. **已有项目/设计系统**：严格继承既有 CSS 变量、组件库和调色板，无需重复打扰用户。
2. **用户已明确指定**：用户在需求中已给出明确风格、配色或参考标杆（如“做成 Linear 暗色”、“主色用数字蓝”），直接按指定执行。
3. **新项目/无既有规范/用户未指定（必须主动带参考链接问询）**：
   **Agent 必须在前置阶段主动向用户发起确认**。提问禁止使用空洞的“你喜欢什么颜色”，必须提供 **3～4 个具备真实工业界/黑客松大奖标杆、附带可点击预览链接（Live Demo Links）的具体选项**，让用户能够提前点开看效果、一键决策：

   - **选项 A（首推标杆）：国内顶级黑客松冠军轻应用流 (Domestic Hackathon Champion Stream / Arco 科技蓝清透质感)**
     - **预览参考**：[字节跳动 Arco Design](https://arco.design) · [飞书开放平台设计规范](https://open.feishu.cn) · [奇绩创坛 MiraclePlus 创新展示](https://miracleplus.com) · [极客公园 AI 黑客松优秀案例](https://geekpark.net)
     - **视觉配方**：**晨光透白背景（`#F6F8FA` ~ `#F7F8FA`）** + **纯白悬浮主卡（`#FFFFFF`）** + **顶栏毛玻璃浮动导航** + **居中 880–960px 沉浸流（去沉重侧边栏）**；主 CTA 科技蓝（`#165DFF`，Arco蓝，微回弹）；低饱和清透微胶囊状态标签（薄荷绿 `#E8FFEA` / `#00B42A`）；Bento 微卡片大盘 + 28~32px 等宽大数字。
     - **适用场景**：国内消费级轻应用、个人工具、AI 对话/助手、记账/订阅/待办、极简现代 SaaS。
   - **选项 B：现代明净国际 SaaS 流（Stripe / Vercel 质感）**
     - **预览参考**：[Stripe Dashboard](https://dashboard.stripe.com) · [Vercel](https://vercel.com) · [Refero SaaS 库](https://refero.design)
     - **视觉配方**：纯白面板（`#FFFFFF`）+ Slate-50 冷灰底（`#F8FAFC`）+ 1px 细线分割（`#E2E8F0`），主 CTA 高对比纯黑（`#09090B`），翡翠绿（`#10B981`）成功态。
     - **适用场景**：周期记账、B2B/SaaS 工具、数据看板、多模块企业工作台。
   - **选项 C：极客微光暗黑流（Supabase 黑客松视觉大奖 / Linear 质感）**
     - **预览参考**：[Linear](https://linear.app) · [Made With Supabase 优秀作品集](https://madewithsupabase.com) · [Raycast Store](https://raycast.com)
     - **视觉配方**：深邃冷黑（`#09090B`）+ 单像素微光边框（`#27272A`）+ 键盘优先（快捷键高亮），主 CTA 纯白或电光蓝（`#3B82F6`），数字等宽。
     - **适用场景**：开发者工具、运维网关、CLI 伴生控制台、极客效率软件。
   - **选项 D：先锋 AI 与微交互流（Cerebral Valley 黑客松 / Godly 质感）**
     - **预览参考**：[Godly 现代严选](https://godly.website) · [Curated.design](https://curated.design) · [Magic UI 动效集](https://magicui.design)
     - **视觉配方**：深色低对比网格背景 + 卡片微边缘光 + 紧凑 Bento Grid 布局 + 120ms 弹性微交互反馈。
     - **适用场景**：AI 创作工具、Agent 交互面板、创新产品首发。
   - **选项 E：自定义参考**
     - 用户可直接输入具体品牌色 Hex，或粘贴任何参考网站/产品名称（如“参考 Airbnb”、“参考 Apple 官网”）。

**只有在用户确认了风格选项（或明确回复指定字母/链接）之后，才允许正式进入代码实现！**

## 原型的范围与决策原则

1. **围绕核心路径**：围绕用户最重要的一条完整业务路径构建高保真可交互界面，而非敷衍堆砌静态展示卡片。
2. **真实感 Mock 数据**：Mock 数据必须包含常规值、极限长文本、空值与异常状态；明确标示模拟数据，不可将 Mock 演示混淆为真实 API 联调。
3. **既有规范绝对优先**：已有项目严格继承现有组件库、CSS 变量与排版尺度；仅在缺少关键决策信息且会改变实现方案时向用户提问，提问须具体并附带选项。

## 五维视觉方向推导（杜绝固定默认模板）

禁止直接盲目套用风格名称，必须结合以下 5 个维度推导视觉系统：

| 维度 | 考量重点 | 决策落地 |
| --- | --- | --- |
| **用户角色** | 专业开发者/运维 vs 运营/企业员工 vs 个人消费用户 | 紧凑信息密度 vs 高对比规范表单 vs 舒适易读视觉流 |
| **核心任务** | 实时排障、监控分析 vs 流程审批、批量处理 vs 周期记录、内容浏览 | 表格/指标大盘为主 vs 标准分栏与严密校验 vs 呼吸感卡片与列表 |
| **内容密度** | 高密度（数据密集）vs 中密度（标准业务）vs 舒适密度（内容型） | 11–13px 紧凑字阶、低内边距 vs 13–15px 标准字阶 vs 15–18px 宽行高 |
| **品牌与基调** | 严肃金融/开发者工具 vs 现代生产力 SaaS vs 创意消费/轻应用 | 冷灰/深色中性、锐利边框 vs 晨光透白/冷灰底、高对比 CTA vs 微圆角、柔和分离 |
| **平台与视口** | 桌面宽屏（>=1280px）vs 移动触控（<=600px） | 居中沉浸流或多列网格、悬停反馈、快捷键 vs 单列流式、底部操作栏、>=44px 触控热区 |

### 五类常见形态的骨架特征与禁忌

1. **现代轻应用与黑客松冠军流（Modern Light App / Hackathon Champion Stream，消费级与轻量工具首选）**：
   - **结构**：**顶栏通透毛玻璃浮动导航 + 居中 880–960px 沉浸流（Center-Staged Flow）** + Bento 微卡片大盘指标 + 单列清晰业务区。
   - **核心优势**：彻底消除传统后台庞大侧边栏带来的压抑感与视觉噪音，用户注意力 100% 聚焦在核心资产与操作流上；单手/移动端可无缝自适应为单列流。
   - **轻工具严禁大后台**：面对个人财务/记账、待办清单、个人工具、AI 对话/助手等轻量场景，**严禁无脑默认采用左侧大侧边栏 + 面包屑 + 管理后台布局**。
   - **严禁生搬硬套 macOS（杜绝恐怖谷与廉价感）**：**坚决杜绝在纯 Web 端刻意模仿 macOS 侧边栏与假红绿灯装饰**。纯 Web 缺少原生 Swift 渲染管线的物理动态模糊、窗口层级与触控阻尼，刻意仿造在 Web 呈现出极强烈的“山寨感、别扭感与恐怖谷效应”（已被用户否决：“做不出来像苹果生态那种的，刻意的仿造反而有些奇怪”）。Web 应用必须走现代 Web 顶级黑客松原生、通透、高响应的轻应用流！
2. **管理后台与企业大型工作台（Admin / Enterprise Console）**：
   - **结构**：紧凑侧边栏/顶栏导航 + 面包屑 + 数据汇总条 + 核心数据表格/分栏列表。
   - **适用**：仅用于多部门、权限复杂、菜单层级深的重型企业控制台。
   - **避免**：把连续业务记录切碎为四处悬浮的圆角卡片；避免大面积装饰性渐变。
   - **卡片界限**：卡片仅用于并列的大盘指标（3–4 个同高指标卡）或多源异构汇总区。
3. **业务工具与控制面板（Utility / SaaS Dashboard）**：
   - **结构**：清晰的页面标题 + 操作栏（搜索/筛选/主操作）+ 主列表或主工作区。
   - **重点**：列表行高度一致、数字严格等宽对齐、状态标签语义明确。
4. **内容与个人工具（Consumer / Notes / Reader）**：
   - **结构**：主从分栏（Master-Detail）或单栏沉浸，正文宽度收敛（680–800px）。
   - **重点**：文字行高 1.6–1.8，字重克制，支持阅读节奏。
5. **营销落地页（Landing Page）**：
   - **结构**：Hero 首屏（强标题 + 一句话副标 + 主 Action + 真实界面预览）+ 3–4 栏功能对齐 + 社会认同与定价。
   - **适用**：仅在落地页中允许使用高质量微光或环境光背景，但核心文字对比度仍须严格达标。

## 商业级明净度与色彩角色（根除泥脏感与语义混乱）

AI 生成界面常出现“文青羊皮纸泥黄底”、“砖红正向按钮”或“大紫大蓝 AI 答辩”。必须执行以下色彩铁律：

### 1. 底色明净铁律（严禁非必要泥黄色）
- **通用业务与工具底色**：强制采用纯白（`#FFFFFF`）搭配清透晨光透白/冷白中性灰背景（晨光白 `#F6F8FA`、Slate-50 `#F8FAFC`、Zinc-50 `#FAFAFA` 或 Gray-50 `#F9FAFB`）。
- **严禁泥脏感**：除明确的复古纸质电子书阅读器外，**严禁在工具、后台和财务应用中使用发黄、发褐的泥米色或陈旧纸张色（如 `#FBFAF7`、`#F4F1EA`、`#EEE7DB`、`#E9E5DC`）**。此类配色在数字屏幕上呈现出极重的灰暗油垢感，严重损害软件的现代感与品质。

### 2. 主操作（CTA）语义铁律
- **主正向按钮**：新建、保存、提交等核心 CTA 必须使用高对比科技蓝/冷靛蓝（`#165DFF` / `#0284C7` / `#2563EB`）或中性深黑（`#09090B` / `#0F172A` / `#1D2129`），与按钮文字保持 >= 7:1 极高对比度，配备微回弹（`active: scale(0.98)`）。
- **严禁主操作语义冲突**：**严禁将暖砖红、陶土红或焦橙色（如 `#AC5034`、`#9E472A`、`#C2410C`）用作主要正向操作按钮**。在人机交互心理学中，暖红/砖褐色天然关联“危险、警报、删除、取消”，用作主按钮会导致用户产生操作犹豫与不安。

### 3. 色彩角色系统（Semantic Color Roles）
禁止在 CSS 中随意散落无语义的 Hex。严格定义语义变量：
- **容器与背景**：`bg-base`（页面底色，晨光白/冷灰/浅白）、`bg-surface`（面板/卡片纯白）、`bg-muted`（次级悬浮、输入框背景）。
- **边框与线条**：`border-subtle`（`#E5E6EB` / `#E2E8F0`，1px 清晰分割）、`border-strong`（输入框、激活态边框）。
- **文字层级**：`text-primary`（`#1D2129` / `#0F172A`，对背景 >= 7:1）、`text-secondary`（`#4E5969` / `#475569`，>= 4.5:1）、`text-muted`（`#86909C` / `#94A3B8`，辅助说明）。
- **强调色**：全局仅允许 **1 个主强调色**。
- **状态语义色**：必须采用低饱和微底 + 高对比文字搭配：
  - **Success（激活/成功）**：Emerald/Mint Green（底色 `#E8FFEA` / `#ECFDF5`，文字 `#00B42A` / `#047857`，边框 `#B7EB8F` / `#A7F3D0`）。
  - **Warning（临近/警告）**：Amber/Warm Orange（底色 `#FFF7E8` / `#FFFBEB`，文字 `#FF7D00` / `#B45309`，边框 `#FFE4BA` / `#FDE68A`）。
  - **Danger（失败/删除）**：Rose/Red（底色 `#FFEAE8` / `#FEF2F2`，文字 `#F53F3F` / `#B91C1C`，边框 `#FFCCC7` / `#FECACA`）。
  - **Neutral/Inactive（已取消/中性）**：Slate/Cool Gray（底色 `#F2F3F5` / `#F1F5F9`，文字 `#4E5969` / `#64748B`，边框 `#E5E6EB` / `#E2E8F0`）。

### 4. 国内顶级黑客松冠军轻应用流标准 CSS 变量模板（开箱即用配方）
面向轻应用、个人工具与现代 Web 交互，Agent 可直接基于以下标准 Token 模板构建：

## 排版规范与信息层级（杜绝伪文人套路）

字体与数字排版决定了 80% 的软件质感：

### 1. 字阶与行高标准
- **大标题 (Page Title / H1)**：24–28px，行高 1.25，字重 700，字间距 tracking -0.02em。
- **区块/弹窗标题 (Section / H2)**：16–18px，行高 1.35，字重 600。
- **正文与表格 (Body)**：13–14px，行高 1.5，字重 400（常规）或 500（重点）。
- **微型标签与元信息 (Meta / Caption)**：11–12px，行高 1.4，字重 500，搭配 `tabular-nums`。

### 2. 财务与数字排版铁律
- **强制等宽数字**：涉及金额、日期、百分比、版本号与计数的文本，**必须声明 `font-variant-numeric: tabular-nums;`**，确保纵向对齐，消除视觉抖动。
- 金额展示应保持基线对齐，小数点与货币符号与主数值同基线，辅助小数部分可微降明度（如 `font-size: 80%`）。

### 3. 排版去油与中英文规范
- **严禁标题末尾加句号**：严禁在 `H1/H2` 标题末尾加上假装极简的句点（如 `订阅概览.`）。
- **严禁假大空副标**：功能性页面禁止堆砌“你的日常，按月整理”等散文诗，副标应简洁说明功能范围（如“管理周期性账单与自动续费支出”）。
- **严禁强制外文贴纸**：避免在中文标题下硬塞无实际含义的 ALL-CAPS 英文缩写（如 `SUBSCRIPTION JOURNAL`）。
- **间距韵律（外疏内密）**：严格遵循 4/8px 进阶基准（4, 8, 12, 16, 24, 32, 48px）。容器内部元素间距（如标题到说明 6–8px）必须严格小于容器外间距（如卡片间距 16–24px）。

## 组件、图标与交互细节

### 1. 图标规范与禁止贴纸化
- 统一使用一种矢量图标族（如 Lucide / Heroicons），标准线宽 1.5px 或 2px，尺寸 16px 或 20px。
- **严禁使用原生系统 Emoji（🚀 ⚙️ 💡 📁）作为界面功能图标与导航项**。
- **严禁使用随机马卡龙颜色循环**：列表中的服务/项目图标容器应采用统一的冷灰中性底色（`#F1F5F9`）与中性深色字，**严禁通过 `:nth-child(3n)` 为图标随机分派粉黄紫绿背景**（杜绝幼儿园贴纸感）。

### 2. 键盘与触控无障碍
- **焦点环（Focus Ring）**：所有可交互元素在键盘 Tab 导航时，必须具有清晰可见的高对比焦点环（`outline: 2px solid var(--accent); outline-offset: 2px;`），**严禁全局 `outline: none`**。
- **触控热区**：在移动端或触摸设备上，可点击区域（可通过 padding 扩展）必须 >= 44x44px。

### 3. 克制动效与偏好尊重
- 微动效仅用于状态反馈（弹窗展开、列表淡入、抽屉推入），时长严格控制在 80–180ms，使用柔和 ease-out 曲线。
- 严禁每个组件在页面初次渲染时浮夸翻转或四处滑入。
- **必须支持** `@media (prefers-reduced-motion: reduce)`，在该模式下彻底禁用位移与缩放动画。

## 全状态防御与数据韧性

商业级界面必须防御完整生命周期状态，杜绝仅有“刚好 3 条漂亮数据”的黄金幻觉：

- **Loading（加载中）**：
  - 异步提交按钮必须立即呈现禁用态并显示等待文案/微型 Spinner，**严禁重复点击造成并发副作用**。
  - 数据首屏加载使用与真实布局尺寸一致的骨架屏（Skeleton）或居中清晰状态指示，杜绝页面跳动（CLS）。
- **Empty（缺省空态）**：
  - 区分“系统无数据”与“搜索/筛选无结果”；
  - 给出明确的原因解释与下一步行动引导按钮（如“新建记录”或“重置筛选条件”）。
- **Error（异常失败）**：
  - 表单校验失败时，精准定位到出错字段并呈现内联提示，**严禁清空用户已输入的内容**。
  - 请求失败提供原位重试按钮。
- **409 版本冲突韧性**：
  - 检测到并发编辑冲突（409 Conflict）时，完整保留用户当前修改内容，明确提示冲突产生原因，并提供“载入最新记录”或差异对比选项，**严禁盲目静默覆盖或整页崩溃**。
- **极端文字与视口防御**：
  - 容器必须声明 `overflow-wrap: break-word;`，在 320px 窄屏宽度下无异常横向滚动，超长单行文本通过省略号截断并提供 `title` 或 Tooltip。

## 视觉与交互验收清单 (Visual & UX Sanity Checklist)

在任何界面任务宣布交付前，必须对照本清单逐项自检：

- [ ] **视觉推导**：方向是否依据用户、任务、密度与平台推导，而非无脑套用单一模板？
- [ ] **空间骨架**：消费级/工具/轻量应用是否采用居中沉浸流（880~960px）而非重型后台侧边栏？
- [ ] **杜绝山寨 macOS**：是否彻底消灭了生搬硬套的伪 macOS 侧边栏与装饰性红绿灯？
- [ ] **底色明净**：是否消灭了发黄、发灰的泥米色（`#FBFAF7` 等），保持晨光透白（`#F6F8FA`）与纯白主卡？
- [ ] **微胶囊状态**：状态标签是否为低饱和清透微胶囊（薄荷绿 `#E8FFEA` / `#00B42A` 等）？
- [ ] **CTA 语义**：主要正向操作是否为高对比科技蓝（`#165DFF`）或深石板黑？是否杜绝了砖红/陶土色主按钮？
- [ ] **排版去油**：是否消灭了标题末尾的句号（`.`）与浮夸散文副标题？
- [ ] **数字对齐**：金额、日期与指标是否已声明 `tabular-nums`？
- [ ] **图标一致**：是否消灭了系统原生 Emoji 与随机马卡龙彩色贴纸图标？
- [ ] **视口自适应**：在 1440px 宽屏、390px 手机与 320px 极限宽度下，均无非预期水平溢出？
- [ ] **状态完整**：Loading（防并发双击）、Empty（带引导）、Error（保留输入）、409（保留草稿）是否均可观察？
- [ ] **无障碍保障**：Tab 导航可见焦点环是否生效？移动端触控热区是否 >= 44x44px？是否支持减少动画？
