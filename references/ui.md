# UI 与交互

用于新界面、交互重构与视觉调整。目标是让用户完成任务、读懂反馈，并形成有依据的视觉表达；主文件的范围和决策规则始终适用。

## 先组织任务与信息

沿用户最常做的一条路径确定页面职责，例如“筛选任务 → 查看详情 → 修改负责人 → 确认保存”。核对每一步需要的上下文、主要行动与结果，不先按组件库的卡片种类排版。已有系统沿当前路径修正，不因这项检查重画整个产品。

在代表性内容上检查信息优先级：用户做决定所需的字段是否可比较，次要说明是否挤走主要任务，列表进入详情后是否保留筛选与返回位置。只读信息、可编辑属性和危险操作应有明确区别。空态应指向可执行的下一步；无权限、加载失败和没有数据不能呈现成同一种空白。

精修先选当前最影响任务的一处关系，留下修改前后的依据：例如把列表中反复出现的长说明移到详情，让状态和负责人仍可比较；窄屏将次要列折入可展开摘要，保留编辑与返回入口。对同一内容和尺寸复核，不能通过删掉业务信息或换短数据制造整洁。

## 从任务推导视觉

先继承既有品牌、组件和 tokens，再考虑用户明确选择；缺少规范时用下面的维度推导并简述理由。合理默认方案可以直接制作成可审阅原型；只有真正影响结果的缺失决策才问，不固定要求先选 3～4 个风格。

新产品或方向遭否定时，先按 [开工澄清](intake.md) 区分已确认偏好与待选方案；用户要求比较时，默认只授权比较片段。颜色达标、组件可操作与用户认可产品质感是不同证据，不能用前两项替代第三项。

新产品需要定制界面时，先满足主文件的复用与核心可行性关口，不能让 UI-First 把关键能力验证延后。用户明确只评审视觉片段时仍可独立推进，并注明模拟与未验证的产品边界。

| 维度 | 要落实的选择 |
| --- | --- |
| 用户 | 阅读舒适度、术语、熟练程度与辅助技术需求 |
| 核心任务 | 浏览、录入、比较、批量处理或实时排障；把主操作放在任务路径上 |
| 密度 | 数据表格、主从工作区或内容流；密度不能靠让必要文字难读来换取 |
| 品牌 | 已有色彩、字体、明暗基调与语气；暖色也可用于经用户选择的品牌和正向操作 |
| 平台 | 桌面并列操作、移动触控、键盘与窄视口重排 |

轻量个人工具可从居中主工作区与精简导航开始；长期跨模块操作可用侧栏；监控可用紧凑表格与详情分栏；阅读可收敛正文宽度、舒适行高；落地页围绕真实价值与主行动组织。不要把毛玻璃、Bento、920px、侧栏禁令或一套字阶当所有产品的骨架。不要编造用户评价、业务指标、获奖称号或社会认同。

无品牌时，可用 [视觉预设](visual-presets.md) 的清透浅色或冷黑深色起步；修改颜色后重新计算。仅在需求或已有规范要求时做明暗切换，避免把视觉优化扩成新功能。

用户要求有记忆点、风格各异或优秀动效时，按 [艺术方向与动效](art-direction-motion.md) 建立表达。先决定产品要让人感受到什么、核心对象如何呈现，再选择布局与效果；不能把所有新产品套入同一套卡片、渐变和入场动画。

## 先完成一条真实感路径

定义入口、用户动作、成功后的可见结果和失败时下一步。原型用真实感的本地模拟数据连接动作；明确标示模拟、是否持久化及未接通的能力。静态按钮不算可交互；“取消记录”不能写成“已取消第三方扣费”。

挑选代表性内容：正常数据、长中文/英文名称、大数字、无数据、无筛选结果及适用的异常。不要求静态阅读页制造无用的加载与网络错误。

| 阶段 | 该阶段的完成证据 |
| --- | --- |
| 原型 | 主路径可操作，适用状态可重现，模拟与存储边界可见 |
| 视觉实现 | 真实内容下层级、排版与响应布局可检查；关键操作不被遮挡或挤坏 |
| 真实集成 | 表单与运行时契约一致，成功反馈对应实际状态；关键错误可恢复 |
| 交付 | 相关测试/构建与浏览器证据分别报告，保留具体未验证项 |

这是验收尺度，不是每项小改动必须重跑的四阶段审批流程。

## 颜色与排版

建立控件体系或完善按钮、输入和状态配色时，读 [控件与配色规范](controls-and-color.md)，把语义 tokens、实际行为和可审阅状态连起来。视觉预设只提供起点，不能凭正常态截图宣称规范完整。

使用角色变量区分页面、表面、边界、主/次/辅助文字、主操作前景/背景、focus 与状态文字/底色。常规正文、辅助说明、占位文字、小字号标签和按钮文字按实际背景至少 4.5:1；大文字门槛是 3:1，判断大小按 WCAG 的定义。7:1 可作为更高可读性目标，不宣称所有按钮必须达到 AAA。测 hover/active、透明叠色与所有实际承载表面，不根据“浅灰”“绿色”猜达标。

交互边界、必要图形及焦点指示检查与相邻颜色至少 3:1；不强制所有装饰分隔线满足此值。状态同时用文字、图形或位置表达，颜色不是唯一信号。品牌色可用于主行动，但危险操作要有独立文案和足够区分。

字阶与宽度以当前任务和真实字体为准：专业表格可紧凑，长阅读宜更舒展；必要信息不要统一缩到 11px。核对中文字体、混合文字、缩放与实际行长。金额/日期等需要列对齐时用 `font-variant-numeric: tabular-nums`，保留单位、基线和准确精度。

间距使用项目已有尺度，内部相关元素更近，不相关区块更远。标题、说明、状态和下一步行动各有职责；功能工具的文案说明范围与结果，内容产品保留其品牌语气。图标复用一套可用风格；不为单个按钮安装图库，Emoji 是否适合由场景与用户选择决定。

### 已有方向的排版精修

用户反馈“字体、间距不舒服”时，先核对排版与密度，避免直接换风格或加装饰。读取实际渲染字体、字号、行高、字重、字距和组件几何；声明了 Inter 等字体但未加载，不等于正在使用它。无字体资产时给出可用的拉丁与 CJK 回退，不把 Windows 结果当作其他平台的字体证据。中文正文和标题通常先用正常字距；英文品牌字距、等宽编号和数字对齐按角色单独处理，不把中文或普通英文服务名全部等宽化。

为当前界面写清少量排版角色，避免大多数内容都落在一个小字号。以下仅是专业工作区的可调整起点，阅读、品牌页面与现有设计系统另行决定：

| 角色 | 可尝试的起点 | 检查内容 |
| --- | --- | --- |
| 任务正文、列表标题 | 14–16px，行高 1.5–1.75 | 中文与混排真实内容是否易读；移动端不为塞入列而缩小 |
| 按钮、输入与重要属性 | 13–14px，行高 1.5–1.7 | 文案完整、控件高度与文字基线一致 |
| 时间、编号与辅助标签 | 12–13px | 保留足够对比度；关键任务信息不伪装成辅助文字 |
| 区块标题 / 页面标题 | 16–18px / 24–32px | 字重与间距能形成层级，不依赖全面加粗 |

将间距落在当前项目的一组尺度上，例如 4/8/12/16/24/32；相关标题与说明更近，区块之间更远。核对共同左边线、列宽、按钮高度和文字基线，区分字形看起来的光学偏差与盒模型偏差。不要用统一加大 padding 来制造精致感；小字配大空隙会让界面同时显得细碎和松散。

在正常视口和真实长内容下检查任务出现的位置：摘要、说明和装饰性趋势是否把主要列表或操作推到过低；窄屏是否仍保留无必要的侧栏占位。按优先级合并概览、收敛重复说明、移动辅助区块，并同步 DOM 与视觉阅读顺序，保留必要的模拟/结果边界。用修改前后同尺寸截图说明排版变化，分别记录视觉观察与行为回归；测试通过不能证明字体与间距已被用户认可。

## 组件与可访问性

- 操作使用原生 button，导航使用 link；表单关联 label、帮助及错误信息。图标按钮有可读名称，非提交按钮明确 type。
- 有显式保存的编辑界面，区分未保存输入与已保存结果。关闭、取消和导航时核对草稿策略，明确保留范围或放弃后果；不要静默把取消改成保存。保存按钮变为不可用后，焦点仍须落在可操作位置。是否保留草稿、自动保存或提示，由任务和既有行为决定，不给每个表单增加审批弹窗。

真实接口接入后，重新检查失败与冲突状态的可操作性：失败时保留输入，不显示已保存；保存被禁用时焦点可进入恢复行动。最新服务器数据与本地草稿分开呈现，只有明确载入或产品既定的合并规则才替换输入。核对版本及相关内容未变且现有写入规则允许时，可保留草稿继续编辑与提交；确有冲突时不能只换版本号重发旧字段。加载、核对版本与保存使用准确的动作标签，不把所有 pending 都叫“正在保存”。

- 键盘可完成主路径，焦点清晰且不被粘性栏或 overflow 裁掉。弹窗建立适当的焦点范围、Escape 行为及关闭后的焦点返回；提交中关闭是否允许与真实操作语义一致。
- 移动触控默认以 44×44 CSS px 的可点区域为舒适目标，包括关闭按钮。WCAG 2.2 AA 的目标尺寸要求为 24×24 或符合间距/其他例外；44px 是本预设建议，不把它误称统一 AA 标准。
- 长文字选择换行、展开、详情或截断：关键字段不能只能靠 hover 才能读全。按钮标签不折成竖排，不用省略号掩盖关键动作；网格考虑 min-width 与实际中文宽度。
- 窄视口重排主工作区，表格确需横向浏览时限于明确容器；在断点两侧检查。页面放大后仍能读和操作；不能只看桌面漂亮截图。
- 动效可服务状态理解、空间关系、叙事与品牌表达；频繁操作的任务路径以清晰、及时为先。`prefers-reduced-motion` 下移除不必要的动画、滚动及 hover/active 位移/缩放，不能只去掉 transition 而留下 transform 跳变；保留操作结果与阅读顺序。复用现有动效设施，无需要时不引入库。

## 完整状态与写入恢复

| 状态 | 行为与证据 |
| --- | --- |
| Loading / saving | 显示进度，避免重复副作用；保留布局与已有输入 |
| Empty | 区分尚无记录与筛选无结果，给出对应下一步 |
| Error | 就近解释，保留输入，字段错误与请求失败分别处理 |
| Success | 由真实提交结果确认，更新列表/版本/摘要等受影响状态；mock 成功明确为模拟 |
| Conflict（接口确有 409 时） | 保留草稿；提供检查最新值或显式重载路径；不自动换版本提交整份旧字段 |
| 超时/连接中断 | 判断是否可能已提交；结果不明时显示待核对，用已有查询/操作标识恢复，不能直接重发非幂等写入 |

已存在数据刷新失败时，说明显示的是旧数据及失败原因，避免旧列表看似已同步。只读请求可提供重试；写请求要按本系统的事务、版本与幂等规则处理。只做视觉修改时保留原状态机，发现行为缺口具体报告，别暗中创造新后端协议。

表单的字段名、选项值、单位、必填、边界和提交形态与实际 API 对照；展示名称与提交值可不同，但映射必须已定义。组件看起来正常和类型通过不能证明契约兼容。

## 浏览器检查与交付

### 明确谁负责滚动

先按任务确定滚动边界。阅读、落地页和长表单可自然整页滚动；持续操作的工作区通常让组织/导航与关键筛选保持可达，内容区独立滚动，详情表单和较长导航拥有各自必要的区域。不要把所有页面锁成 `100vh`，也不要让工作台默认随整页滚走。

工作区按实际容器高度分配空间，核对 flex/grid 子项的最小尺寸与 overflow；父框架裁切之前，必须给完整内容一个可到达的滚动区域。小高度、动态视口、移动键盘或放大时，收敛重复概览，或让相应区域自然滚动，不能把操作藏到裁切外。弹层保持正确的定位边界，不能为了锁住背景而裁掉 portal、选择器或焦点。

优先原生滚动与项目已有设施，滚动条与表面统一但不隐藏可发现性。不要为细节精修自写滚轮劫持、模拟轨道或引入平滑滚动引擎。需要时保留滚动槽以减轻筛选前后的跳动，并尊重系统高对比度；无法承担验证成本时使用平台默认表现。

实际从顶部滚到末项，验证滚的是预期区域、导航/筛选位置、底部内容、触控/键盘、焦点进入后的自动可见，以及详情/菜单打开关闭。空结果和短内容也要能恢复；滚动条变细或整页无溢出都不能单独算通过。

### 自适应要保留任务能力

按当前任务能否顺利完成判断自适应，不以 `scrollWidth <= clientWidth` 作为总通过条件。先核对目标是整页、侧边预览窗、分栏工作区还是可嵌入控件，以及实际可用宽度；页面媒体查询与组件容器查询按既有栈选择，不强制新增响应式库。

| 场景 | 需要看到的结果 |
| --- | --- |
| 宽工作区 | 属性可比较，列宽服务真实内容；大空白与过小字号不冒充精致 |
| 中间宽度 / 分栏 | 主内容不被导航挤坏；列可合并为摘要，字段与功能仍有明确入口 |
| 窄屏 | 阅读与触控顺序重新组织；导航有可用替代，关键状态、负责人等按任务保留或可展开 |
| 详情 / 弹层 | 不受错误的容器定位或 overflow 裁切；可退出，输入与保存能到达 |
| 长内容 / 放大 | 中文、英文连续字符串和真实长标题可读；不靠缩小文字、hover 或丢字段通过 |

验证影响到的断点两侧和至少一个实际中间宽度；需要手机 / 窄屏支持时验证对应使用场景。不要只测桌面和两个手机宽度。调整后回到用户实际打开的尺寸再看一次，重置临时视口覆盖。主路径测试包括宽度变化后的导航、筛选、编辑、保存与焦点，不只截静态布局。

检查首个主要任务或操作在页面中的位置：预览工具栏、重复标题、说明与筛选是否占据过多首屏；可折叠比较工具、合并筛选和收敛重复上下文，不减少必要的模拟边界说明。不设适用于所有页面的固定首屏像素上限。

把已写的排版角色、密度和布局策略与实际计算样式、内容和几何对照。若已有规范未落实，先修实现和验证，不继续积累相同规则。对比度、构建与脚本回归分别报告；它们不证明成品质感或自适应已被用户接受。

在可用浏览器中实际走主路径，检查相关的空态、失败、成功、长内容与键盘流程；选至少桌面、窄屏和受影响断点两侧。确认按钮热区、焦点、对比度、溢出、遮挡与必要文案。只对本次范围做适当检查，不把它扩成全产品审计。

使用宿主支持的浏览器工具，保存说明环境与模式的截图/记录。浏览器缺失时做可运行的契约、状态、样式计算与构建检查，明确哪些视觉/键盘结果未验证；源码推理不是实测。截图证明渲染，不能替代真实 API、持久化和业务结果。

标准依据：[WCAG 对比度](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html)、[非文字对比度](https://www.w3.org/WAI/WCAG22/Understanding/non-text-contrast.html)、[目标尺寸](https://www.w3.org/WAI/WCAG22/Understanding/target-size-minimum.html)、[重排时内容与功能不应消失](https://www.w3.org/WAI/WCAG22/Techniques/failures/F102.html)。容器布局方法可参考 [MDN 容器查询](https://developer.mozilla.org/en-US/docs/Web/CSS/Guides/Containment/Container_queries)。这些检查覆盖部分可访问性问题，不构成完整 WCAG 合规认证。
