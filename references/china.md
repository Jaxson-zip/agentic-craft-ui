# 中国用户

产品面向中国大陆用户时读。下面是做出“像国内产品”而不是“翻译过来的国外产品”所需的默认做法；用户或项目另有要求时以其为准。

## 默认步骤

1. 确认目标平台：网页、微信小程序还是 App（见 [平台与组件库](platforms.md)）。
2. 去掉在大陆打不开或很慢的依赖，资源打包进项目或用国内服务。
3. 按下面的中文排版设置字体、字号和数字格式。
4. 登录、支付、分享按国内习惯设计；用不到的不加。
5. 要上线时，提醒用户备案和隐私合规，这些需要用户本人办理。

## 中文排版

| 项目 | 默认做法 |
| --- | --- |
| 字体 | 随项目打包一套中文界面字体，让中文和数字是同一套：`npm install misans`（小米 MiSans，按 `unicode-range` 分片）或 HarmonyOS Sans。字体栈见 [视觉规范](visual-style.md)。不引用 Google Fonts；只靠系统字体时，Windows 上会是微软雅黑配另一套数字字体，看起来别扭 |
| 字号与行高 | 正文 15–16px（手机）/ 14–16px（桌面），行高 1.6–1.75；中文字号比同级英文略大一档才舒服 |
| 强调 | 不用斜体（中文斜体是机器拉斜的，很难看）；用字重、颜色或底色强调。字重常用 400 / 500 / 600，系统中文字体在 Windows 上没有中间字重，要实际看效果 |
| 标点与混排 | 全角中文标点；中英文、中文与数字之间可加一个空格，一个项目内保持统一 |
| 金额 | `¥1,234.00`；较大金额可写“1.2 万”；金额和日期用 `font-variant-numeric: tabular-nums` 对齐 |
| 日期时间 | `10月24日 周六`、`2026年10月24日`、`14:30`；相对时间用“刚刚 / 3 分钟前 / 昨天” |
| 文案 | 口语、简短、直接：“已保存”而不是“操作成功完成”；按钮写动作，如“添加订阅”“去支付” |

## 在大陆能打开

- 不依赖 Google 的服务：Fonts、Analytics、reCAPTCHA、Firebase、Maps、Google 登录在大陆不可用或极慢。
- 依赖用 npm 安装并打包进项目；安装慢时用 `registry.npmmirror.com` 镜像。避免运行时从国外 CDN 加载脚本、字体和图片。
- 替代服务按需选择，常见的有：地图用高德或腾讯地图，验证码与短信用阿里云或腾讯云，对象存储用阿里云 OSS 或腾讯云 COS，统计可用自托管方案。选型仍按 [生态调研](discovery.md) 比较。
- 服务器放在大陆需要域名 ICP 备案；未备案时可以先放在香港或海外，但大陆访问会变慢，要告诉用户这个取舍。

## 国内用户的习惯

- **手机优先**：大多数用户用手机打开。先设计 375–430px 宽度，底部 Tab 导航很常见，主要按钮放在拇指够得到的位置。
- **登录**：手机号加短信验证码、微信登录最常见；邮箱加密码很少用。短信要服务商账号和签名模板，微信登录要在微信开放平台申请应用，这些都需要用户本人办理。
- **支付**：微信支付、支付宝。申请商户号通常需要个体工商户或企业资质，个人开发者没法直接接入，这一点要先告诉用户。
- **分享**：二维码、微信好友和朋友圈、复制链接或口令。网页在微信里分享自定义卡片需要配置微信 JS-SDK。
- **微信内置浏览器**：很多链接是在微信里打开的。它不能直接下载文件，跳转 App 受限，部分新 API 不支持；涉及这些功能时要在微信里实际打开测试。
- **信息密度**：国内用户习惯的密度比欧美产品略高，但工具类产品依然要留白，不要堆满。

## 颜色语义

- 金融、行情、涨跌场景：**红涨绿跌**，和欧美相反。收支场景常见“支出黑色或红色、收入绿色”，按产品定一次后全局统一。
- 红色在节日和促销中是正面颜色，所以错误状态不能只靠红色表达，要配文字或图标。
- 状态颜色仍要满足 [UI 与交互](ui.md) 的对比度要求。

## 合规提醒

上线前把下面几项告诉用户；Agent 不能替用户办理，也不要假装已经满足。

- 大陆服务器和域名要做 ICP 备案，网站页脚放备案号。
- 收集手机号、位置等个人信息要有隐私政策，只收集必要的，敏感信息单独征得同意（《个人信息保护法》）。
- 小程序要在后台配置用户隐私保护指引，并选对服务类目，否则审核不过。
- App 在国内应用商店上架需要 App 备案，部分商店还要求软件著作权。

以上是常见要求，具体以平台和主管部门当前的规定为准。
