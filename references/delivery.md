# 验收与交付

用于行为变化和发布前交付。按改动影响选择检查；小文案调整不要求后端验活，无 UI 的任务不要求浏览器或 ER 图。

## 选命令

读取项目实际脚本、CI 和贡献指南，采用已有包管理器、linter、测试和生产构建方式。例如 pnpm + ESLint 项目继续使用自身 lint/test/build，Python CLI 使用已有 pytest 与必要的打包检查。

不默认执行 `npx @biomejs/biome check --write` 或安装工具。格式化尽量限制到修改文件，避免把无关全仓改动混入任务。构建命令按项目选择；缺少构建流程时说明不适用或缺失，不能编造通过证据。

## 验收矩阵

| 证据 | 证明什么 | 不能替代什么 |
| --- | --- | --- |
| lint / 静态类型 | 已覆盖的静态规则、类型一致性 | 请求与响应的运行时校验 |
| 契约测试 | 真实边界的字段、输入、错误语义 | 完整业务结果与权限验证 |
| 行为回归 | 修复前失败、修复后通过的用户结果 | 未覆盖路径 |
| HTTP smoke | 指定请求在指定环境下可达 | 状态变化、幂等、权限与 UI 联调 |
| 真实 UI 路径 | 界面与实际数据协同 | 全部业务路径 |
| 生产构建 | 当前配置可生成生产产物 | 全部运行时行为、环境差异与安全问题 |

HTTP 按接口规范检查正确状态，不一律要求 200。读写操作还要断言关键响应字段及预期状态变化；对本次改动影响的输入、权限、重试/重复请求和错误路径增加检查。不得用固定的成功对象掩盖无效业务结果。

## 修复闭环

先复现和记录失败证据，选择根因假设，做最小修改，重新跑复现和受影响回归。复现脚本保持精简，但不限制为 15 行；单个用例转绿不是唯一验收，仍需检查影响边界。

检查失败时先判断是本次引入、已有问题还是环境缺失。证据有进展可继续修复；连续两次同因尝试没有新证据时停止盲目重试，整理已知事实，转向日志、隔离实验或请求缺失信息。缺少凭据或外部服务时先完成独立工作，再明确受阻检查；不删测试、降低断言或无限循环来制造全绿。

需要临时服务时使用项目已有启动方式，确认就绪再请求，记录地址与环境。管理自己创建的进程并在检查后清理，不终止用户已有服务。Windows 后台 helper 使用隐藏窗口。部署、数据变更或外部发布遵循用户现有授权；本 skill 不附带权限。

## 业务约束按领域选择

从当前系统提取真实不变量与威胁，而非套通用资金等式。涉及金额、库存、额度或权益时核对单位、精度、并发、事务与重试语义，优先将可独立测试的规则与 I/O 分离，保持现有语言。

列表或提醒依赖“今天”时，核对采用的时区、日历边界，以及页面长时间打开或重新激活后的日期更新。初始化时算出的日期不能一直当作当前日期使用。

多租户或付费 API 路径核对实际身份、授权、隔离、预算与限流。复用项目已有防护，不一律引入 Cloudflare、Upstash 或 RLS；数据库支持 RLS 且设计采用时，核对实际策略与运行身份。组件存在不等于隔离或限流已经生效，相关行为须实测。

## 交付证据

按检查列出命令、结果和环境，区分 `passed`、`failed`、`blocked`、`not-run`、`not-applicable`。展示主路径实际结果；没有运行浏览器或真实 API 时直接标明。截止时间和既有投入不能把 smoke 证据升级为完整验收。

只把达到成功条件的部分称为完成。其余以具体未验证项交接；用户可以决定是否接受限制，但 Agent 不能替用户隐去失败或声称所有检查通过。
