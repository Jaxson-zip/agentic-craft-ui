# 交付指南

做功能、改已有项目、准备交付时读。

## 1. 先复用

- 新产品先花几分钟查：有没有现成产品或服务能直接用（例如订阅管理有 Wallos）？有没有开源底座能改？没有联网工具就说明没查，不要声称市面上没有。
- 认证、支付、复杂表格、编辑器、图表、任务队列，优先用成熟库或服务。自己写要能说出现成方案哪里不合适。
- 交付报告里用一两句话说明：考虑过什么、为什么没直接用。

## 2. 改已有项目

- 先看项目规则、当前 git 状态、已有的脚本和测试，用项目自己的包管理器和命令；先跑一次现有测试，记下基线。
- 读到影响范围为止：相关实现、调用方、测试和配置。用宿主自带的检索和代码索引工具。
- 只改需要改的：保留别人的改动，不顺手重构、改名或格式化无关文件。
- 字段、枚举、单位、错误要和真实接口一致；复用项目已有的校验和工具函数。

## 3. 验证

- **修复**：先复现，再做最小修改，然后重跑复现和受影响的测试。
- **功能**：至少走通一条真实路径，再检查一个失败情况：失败时提示清楚、不丢输入。
- **写入**：保存成功要以服务器返回为准；超时不确定是否成功时先查询再重试，不要重复提交；遇到版本冲突不能用旧数据覆盖新数据。
- **界面**：在浏览器里实际点一遍主路径，桌面和手机各截一张图。
- 同一个原因连续失败两次，就停下来查日志或换思路，不要删测试或放宽断言来“变绿”。
- 只跑和这次改动有关的检查；小改动不用写整套端到端脚本。

## 4. 如实汇报

用 SKILL.md 里的格式：结果、改动、设计（做了界面时）、没验证的。

- 核心路径没跑通，第一句就写没完成。
- 每个“通过”都要能复查：一条命令、一个文件或一张截图；读代码推断的不算通过。
- 没做的检查直接写没做和原因，例如“没有 API Key，真实模型没测”。
- 界面写“待你验收”，不自己宣布好看。
- 需要用户决定或亲自办理的事单独列出来，一句话一件。

## 5. 中国上线提醒

这些需要用户本人办理，Agent 只提醒、不假装已满足：

- 大陆服务器和域名要做 ICP 备案。
- 收集手机号、位置等个人信息要有隐私政策，只收必要的（《个人信息保护法》）。
- 小程序要配置用户隐私保护指引并选对类目；App 上架国内商店需要 App 备案。
- 短信登录要短信服务商账号和签名；微信登录要在微信开放平台申请应用；微信支付、支付宝通常需要个体工商户或企业资质。

## 6. AI 应用

- 模型用大陆能直接访问、兼容 OpenAI 格式的服务（如 DeepSeek、通义千问、Kimi），base URL 和模型名做成配置，方便切换。
- API Key 只放在服务端环境变量里，前端调用自己的接口；不写进代码、不提交进仓库。
- 没有 Key 时提供一个明确标注的演示模式，汇报里写“真实模型没测”。
- 流式输出能中途停止，停止或断线时保留已生成的文字；出错给可重试的提示，不清空用户输入。

## 7. 多人、多租户与协作

- 要给别人用时，先接现成的登录方案，再按用户隔离数据：查询和写入都带上用户或租户条件，并在服务端校验，不靠前端隐藏按钮。
- 宿主支持多个 Agent 并行时，只把互不依赖、不改同一批文件的任务分出去；共享接口先定好再分工，合并前看每个人的实际改动。
