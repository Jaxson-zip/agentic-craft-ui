# 控件与配色规范

用于定义或完善一组交互控件、建立设计系统，或用户反馈“看起来可以但控件不一致”的任务。沿已有品牌和项目 tokens 建立规则；小文案修改不必制作完整组件库。

## 默认步骤

按顺序推进；后面各节是每一步的细则和常见误区。

1. 列出页面实际用到的控件和颜色用途。
2. 按语义角色建立或映射 tokens，前景与背景成对定义。
3. 为每种控件选适用状态，并绑定真实行为（原生 `disabled`、`aria-busy` 等）。
4. 确定少量稳定尺寸：控件高度、padding、圆角、图标和描边。
5. 测量实际配对的对比度，用真实的 Tab、悬停、按下检查状态预览。
6. 分别记录规则、数值检查和浏览器观察。

## 配色先按语义分工

| 角色 | 用途及成对变量 |
| --- | --- |
| 表面 | 页面、纸片/卡片、输入、弹窗、悬停表面；承载文字必须有对应前景 |
| 文字 | 主要、次要、辅助、占位；辅助不等于低到不可读 |
| 操作 | 主操作背景/前景及 hover/active；次要、文字操作按同一层级体系 |
| 边界 | 装饰分隔与可识别的控件边界分开，不用装饰细线替代输入框轮廓 |
| 焦点 | 可见的键盘焦点与偏移/底衬；暗提示条等反向表面单独核对 |
| 状态 | success、warning/pending、error、neutral/info 的文字/底色/必要边框 |
| 不可用 | disabled 的文字、背景和必要边界；loading/busy 有自己的语义与反馈 |
| 品牌/媒介 | 装饰强调、插画、材质颜色；不自动赋予成功、危险或选中含义 |

品牌色可以参与功能角色，但各用途必须有独立的语义映射和文案。正常聚焦不应看起来像输入出错；未保存草稿不是提交失败；多个纸片颜色不自动成为业务状态。颜色不是唯一信号，状态用文字、形状、勾选或位置同时表达。

成对管理前景/背景并测实际配对。常规文字、按钮文字、占位与必要说明按 UI 参考检查 4.5:1；必要边界和焦点按适用条件检查 3:1。禁用控件在 WCAG 相关对比度条款中有例外，仍尽量保持易识别，不把统一 50% 透明度作为规范。透明叠色、图片和反向表面另测。

## 控件状态要与行为一致

为实际出现的控件确定下表中适用的状态。只读展示不制造 loading；普通按钮不强制 selected；没有破坏动作不创建危险按钮。

| 状态 | 表现 | 行为与检查 |
| --- | --- | --- |
| Default | 按主、次、文字/图标操作区分 | 文案是动作，标签、图标与基线一致 |
| Hover | 颜色或适量表面反馈 | 不给 disabled 留活动反馈；触屏不依赖 hover |
| Active | 可辨认的按下反馈 | 位移/缩放按场景选，不让文字和点击热区跳动 |
| Focus-visible | 清楚的焦点圈及间隔/底衬 | 键盘可达，未被裁掉；不能只在颜色接近的背景上画细线 |
| Disabled | 有原因的不可用表现 | 不接受动作；光标不冒充正在等待。可见帮助不只靠不可聚焦按钮上的 tooltip |
| Busy | 状态文字/进度，保留尺寸 | 防止重复副作用，与 disabled 区分；ARIA 属性与实际行为一致 |
| Selected / checked | 持续且明确的选中信号 | 只用于有此语义的控件，核对 aria-pressed / aria-checked 或原生值 |
| Invalid | 就近文字、边框或图形 | 关联帮助、aria-invalid；正常编辑/聚焦不误用错误状态 |

原生 `disabled` 会阻止常规操作并改变焦点可达性；`aria-disabled` 只声明状态，事件处理仍须阻止操作。`aria-busy` 不会阻止重复提交。用合适的原生元素与实际状态更新，不靠 CSS 看起来“不能点”。按钮因保存/提交变得不可聚焦时，把焦点留在合理的可操作位置。

输入有可见 label；placeholder 不能替代它。核对空白、长内容、清空、错误后的继续编辑与成功结果。原生约束和自定义错误保持一致，避免同一失败同时出现浏览器气泡和另一条不同提示。显式保存的草稿规则见 UI 参考。

只读与禁用输入分别决定：`readonly` 的文本字段仍可聚焦和复制；原生 `disabled` 通常不可聚焦且不随普通表单提交。不要只为变灰而禁用业务仍需要提交的字段，核对真实提交契约。

## 尺寸与形态

确定当前项目少量稳定的控件高度、字体、padding、圆角、图标尺寸及描边。艺术化的纸片、品牌图形与操作按钮可以有不同形态，但同类操作不要每个位置另造一套。44px 是舒适触控起点，48px 可用于更突出的主操作；它们不是所有场景的强制尺寸或统一 WCAG 门槛。密集桌面和现有系统按任务选择，并核对实际目标尺寸及间距。

动态图形与装饰不遮住控制区；按钮尺寸不能因 loading 图标、保存文案或错误提示突然变化。缩放、长中文、窄屏和键盘操作下检查热区与布局。

## 可审阅的规范

控件较多或规范本身是交付物时，提供使用实际 tokens 和组件样式的状态预览，不手抄另一套颜色制作“设计稿”。展示适用的禁用、选中、错误、进行中，以及通过真实 Tab、悬停和按下可检查的状态。演示和真实业务反馈分别标明。

分别记录规则、数值检查与浏览器观察：tokens 声明不等于组件使用正确，变量对比度通过不等于所有叠色通过，静态状态板不能替代实际写入/恢复路径。完整可访问性与跨平台表现仍按实际证据报告。

可选预设的 `assets/themes.css` 提供 `.craft-action` 与 `.craft-field` 起点，状态变量由 `tests/test_visual_tokens.py` 检查。已有设计系统优先映射和复用，不要求复制预设或增加新框架。
