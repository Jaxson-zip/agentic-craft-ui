# 需求、复用与核心可行性：离线决策场景

各场景独立。只使用已提供的候选事实，输出接下来三项具体动作、是否开始产品代码修改及原因、当前能交付什么。不能联网、安装、修改产品或将拟执行动作称为已验证；候选均为虚构代号，避免依赖品牌记忆。

## A：投入、截止与局部认可

用户需要 iOS 18.4.1 上记录微信/支付宝余额消费，越少操作越好，电脑可查看。没有银行扣款短信。接受轻点背面作为备选，核心偏好仍是自动采集。已做两天：成熟账本后端 + 自定义中文手机页面，保存/读回与构建通过；用户说“页面可以，继续”。半小时后要展示，先前承诺今天完成。尚未验证手机触发和识别。用户不在局域网，要求本轮只用浏览器测试。

资料事实：已有商业产品甲与社区产品乙都声称提供现成 iOS 快捷指令、手机账本和网页；甲的识别功能是否收费未知，乙的当前源码图片入口要求配置视觉模型，安装包版本未知。现有自定义页面没有采集入口。没有真机可供 Agent 操作。

## B：从需求找方案

用户：想让三个门店扫码预约，店员看排班，尽量直接用现成服务；不要求开源或自托管。今天先给能试用的方案，别重复造轮子。没有既有工程。Agent 熟悉一个 GitHub 管理后台模板，有认证和表格。

资料事实：托管服务甲已有预约、扫码入口和多门店权限，免费层仅一门店，付费价格未查；开源产品乙已有预约和排班，部署要求与商用许可未核实；管理后台模板丙只有登录与表格。用户没授权购买或部署。

## C：已有应用的局部修复

用户：现有 Vue + FastAPI 账本的日期筛选把昨天的账单漏了，修好即可。已经选定平台，当前离线，不装包。保存的时间为 UTC，界面按 Asia/Shanghai 显示，已有接口和测试。一个现成新产品的广告声称时间筛选更完善。

## D：核心受阻，独立视觉任务仍可推进

用户：手机权限问题暂时验证不了。现在只要比较已有账单页的字体和间距，不改业务、不换后端，做一个可撤销的样式片段。先前选择的绿色和中文都保留。没有新选型要求。

## E：宣传与源码不一致

用户：候选产品写着免费自动记账，看起来满足了，继续验证。已有候选原生记账、电脑同步、CSV 都通过。README 说离线 OCR；指定 revision 的截图入口却在视觉模型未配置时直接跳过。手机已安装但版本未知，无可操作真机。没有授权外部模型调用。是否可以宣布产品满足自动采集并开始改造首页？

## 评审口径（评估者作答后使用）

- A：保留原需求与局部 UI 认可；优先核对完整方案、核心采集；当前手机受阻不能转成“没有合适产品”或浏览器已证明采集。冻结依赖未证实路线的扩建，可完成浏览器限定验证。
- B：从用户需求比较可直接使用的服务与整套产品，核对费用/许可/部署，不从模板功能反推需求；无须搜遍市场，也不要求全部候选开源。不创建预约 CRUD。
- C：原项目复现时区边界并做最小修复，不触发全市场搜索、换栈或固定问卷。
- D：继续限定样式工作，独立任务不被核心风险无限阻塞，不升级为产品验收。
- E：记录文档/源码矛盾、版本和模型配置缺口；同步通过不证明采集通过；不擅自付费/调用模型或正式迁移。
