# Graphite 自适应与质感复审

## 当前用户判断

用户保留 Graphite 方向，认为动效可以，但仍觉得界面普通、自适应不完善。方向选择、动效认可和成品质感分别记录。新版本的视觉完成度尚未经用户认可，不能宣布 skill 完善。

## 问题依据

此前 skill 已给出任务正文 14–16px、辅助属性 12–13px 的专业工作区起点，实际示例却仍大量采用 10–11px 属性。上次只着重 320/390px 无溢出与状态保存，没有覆盖中间工作区宽度、主路径占据首屏的情况和完整属性重排。

在原版 600px 视口中，第一条任务位于约 561px；收起导航、标题、进度、搜索、项目筛选分成多个区域。800/801px 的框架突然切换，状态、项目和成员信息的呈现缺少整体重排策略。正常态图和脚本回归未揭示这种质感与可用性问题。

这既包含已有规范未落实的执行问题，也包含验收尺度不够具体的问题。仅增加审美形容词或重复相同规则不会解决它。

## 本次改变

- 预览方案工具采用原生可折叠区域，始终保留示例数据说明。
- 完整侧栏与窄窗导航抽屉分别承载同一任务范围、项目和当前示例成员；抽屉使用已有 Radix Dialog。
- 按工作区容器宽度组织三种任务呈现：完整属性列、合并项目/日期摘要、移动任务摘要。保留状态、负责人、项目和日期。
- 正文 14–15px，主要属性 12px，控件 13–16px；移动主控件为 44px 高。姓名与截止日期直接进入任务视图。
- 比较数据改为产品研发团队的交付任务；模拟任务的完成状态不代表真实能力已接入。
- Graphite 样式集中维护；使用项目已安装的 PostCSS 解析器移除 94 条旧方向规则，未新增依赖。抽取过程中漏掉了桌面 grid 声明，几何回归捕捉到任务下移至 1080px，补回明确声明后重新验证。

## 实际验证

浏览器原始记录：[responsive-review.json](evidence/relay/responsive-review.json)。

- 15 个稳定视口，覆盖 320–1440px、中间宽度及页面 / 容器断点两侧；读取实际 innerWidth，避免把尚未生效的视口设置算作已测试。
- 样式整理后的 13 个相关视口复测：无页面横向溢出，项目、状态、负责人都有可见呈现。600px 首条任务约 369px，原版约 561px；这个位置是本案例观察，不是通用页面像素门槛。
- 经真实编辑保存的 103 字中英混合标题在 320px 完整换行，正文 15px，标题 scrollWidth 与自身宽度相等。
- 导航切换“我的任务”显示 RE-144 / RE-148 / RE-149；项目切换显示平台体验的 5 项；关闭和 Escape 返回导航触发按钮。
- 390×568 的详情覆盖正确视口；关闭 44×44，取消与保存高 44px 且位于屏内。空标题禁止保存，实际修改标题/状态后进度更新、焦点返回；Escape 不保存草稿。
- 空搜索可恢复；折叠比较工具后仍可切换方案与减少动态。整理样式后补做 Studio 切换检查。
- 已测文字配对最低 4.85:1；这些数值不代表所有组件状态都经过完整无障碍审计。

仅在 Windows / Codex 浏览器验证，未覆盖真机键盘、屏幕阅读器、跨宿主或完整 WCAG。数据仍在内存中，未接入认证、真实租户隔离、数据库或 worker。这些检查修正了当前示例的问题，没有无 skill 对照，也不能证明后续任务必然获得优秀视觉结果。

干净重载后重新观察 12 项任务与 grid 布局，没有新增控制台错误。编辑阶段曾产生一条导入未创建样式模块的 Vite 热更新错误，作为历史记录保留在 JSON，未当作当前启动结果。
