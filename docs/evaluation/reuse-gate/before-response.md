# 冻结 before skill 的离线决策回答

以下场景相互独立。依据仅为冻结的 SKILL.md、discovery.md、intake.md、delivery.md，以及场景给定事实。本轮只做决策，没有联网、安装、操作产品或运行验证；“接下来”均为拟执行动作，不能当作已完成证据。下文“是否开始”描述恢复实际执行后的决策，本轮不修改任何产品代码。

## A：投入、截止与局部认可

接下来三项具体动作：

1. 将展示范围与验收拆开：已有账本后端和中文页面的保存/读回、构建仅沿用场景所述通过记录；“页面可以”记录为页面的局部认可。单列“手机触发→获取可识别输入→识别消费→入账→电脑读回”的目标路径，将触发、识别及端到端结果标为未验证，并说明今天的承诺和两天投入不改变这些状态。
2. 按同一条采集入账路径整理甲、乙和现有实现的复用比较：甲有现成快捷指令、手机账本和网页的资料声明，识别收费待核对；乙有同类声明，但指定源码图片入口依赖视觉模型，安装包版本待核对；现有系统已有账本和页面，却没有采集入口。保留成熟产品作为候选，不能用独立中文页面、已有测试或截止时间将其淘汰，也不能把声明当成实际能力已通过。
3. 将半小时展示限定为浏览器可核对的现有页面、保存及电脑端读回，并准备具体的后续手机验证步骤：核对实际安装版本和入口，再验证自动或轻点背面触发、识别、实际入账和失败情况。本轮无法操作手机，也不满足远程手机验证条件，明确保留这一限制；浏览器检查即使通过，也不据此宣布手机自动采集完成。

是否开始产品代码修改：**暂不开始新的产品代码修改。** 当前优先事项是明确采集方案的复用边界和核心路径证据；现有页面没有采集入口，手机触发与识别也未验证。不能因赶展示而直接补造一套自建采集设施，或把用户对页面的认可解释成对技术路线及自动采集的验收。已有可独立进行的浏览器检查可以继续，不需要重复请求其授权。

当前能交付：一份范围明确的浏览器展示安排、现有账本能力与采集缺口清单、甲乙及现有实现的复用决策表，以及真机验证待办。现有保存/读回与构建只能标为“场景已有通过记录，本轮未复跑”；核心采集是 `not-run`，当前会话真机检查受条件阻碍。不能交付“自动记账已完成”的结论。

## B：从需求找方案

接下来三项具体动作：

1. 固定目标路径为“三个门店的顾客扫码预约→归属正确门店→店员按权限查看排班”，采用用户已说明的托管可接受、尽量直接用现成服务的约束，不再询问是否必须开源或自托管。
2. 给出分层比较和推荐：优先试用托管服务甲，因其已有预约、扫码与多门店权限；明确免费层一门店无法证明三店目标已满足，付费价格及试用条件待核对。乙作为备选，部署要求和商用许可均未知，不能当作已排除或已可部署。丙只有认证和表格，无法承载目标业务路径，不以熟悉它为由搭建预约排班系统。
3. 准备甲的试用核对步骤和三店验收清单：确认是否有无需购买即可体验三店权限的方式，再核对扫码预约、排班及跨店权限。恢复联网后应核对真实试用入口、现行价格与套餐限制；若三店试用必须购买，先提供具体价格与条款供用户决定，不购买或部署。本轮离线且候选为代号，不能提供虚构链接，也不能宣称已有可直接打开的试用环境。

是否开始产品代码修改：**不开始。** 没有既有工程，用户需要的是今天可试用的现成服务方案；甲比后台模板更接近完整目标业务。当前没有证据表明必须降到模板拼装或自建，也没有购买、部署授权。

当前能交付：以甲为首选、乙为备选的方案比较，三店目标与免费层差距说明，以及具体试用验收清单。真实试用入口、付费价格、乙的许可与部署条件均为未核对项；离线事实不足以保证今天已拿到可用的三店试用。

## C：已有应用的局部修复

接下来三项具体动作：

1. 沿现有 Vue 页面、FastAPI 日期筛选接口及已有测试定位时间处理，检查 Asia/Shanghai 的日期如何转换为 UTC 查询边界、结束边界是否包含，以及传参和数据库比较语义。先复现“昨天账单被漏掉”的具体记录与请求，不仅凭时区描述就宣布根因。
2. 用现有测试设施固定失败证据，覆盖上海本地昨天的起点、终点及相邻日期记录；核对是否采用本地日期半开区间，并正确转换为 UTC。若筛选依赖“今天”，同时检查页面跨日或重新激活后的日期更新。
3. 在查明根因后做最小有效修复，复跑失败用例及受影响接口、日期筛选回归；沿用当前依赖与脚本，记录实际结果。离线状态和广告均不构成换平台的理由。

是否开始产品代码修改：**实际执行时可以开始这项局部修复，但先完成定位和失败复现，再改代码。** 用户已明确修复范围、平台和不装包约束，现有接口与测试可用；没有需要先做的新产品选型。新产品广告不提供本项目修复依据，也无需进行全网调研。本轮决策测试仍不实际改代码。

当前能交付：精确到日期边界与接口的排查、回归方案。尚未读到应用源码或运行测试，不能交付已证实的根因、补丁或“已修好”的声明；相关检查均为 `not-run`。

## D：核心受阻，独立视觉任务仍可推进

接下来三项具体动作：

1. 读取已有账单页的样式和复用组件，固定同一份中文账单内容与现有绿色方向，圈定只涉及字体、字阶、行高、间距的可撤销样式范围，避免改变数据、表单绑定或后端契约。
2. 基于同一内容制作局部字体和间距比较片段，例如“较紧凑的信息密度”和“较舒展的阅读间距”，保留绿色与中文。用局部覆盖或独立预览承载，记录恢复方式，不提前扩展为整套页面重做。
3. 对比较片段做适用的浏览器检查，核对长中文、金额对齐、窄屏阅读与控件可操作性，呈现可审阅比较，等待用户选择后再扩展选中的排版方案。手机权限问题继续单独记录，不把样式比较作为采集能力的验证。

是否开始产品代码修改：**实际执行时可以开始用户已授权的可撤销局部样式片段。** 这是独立、低影响的视觉任务，绿色、中文、业务和后端边界已明确，手机权限受阻不妨碍排版比较。不重新选型，也不重复询问已确认的品牌选择。本轮仍只输出决策，不实际生成或修改产品片段。

当前能交付：两种排版片段的具体制作范围、比较标准及恢复安排；本轮没有制作预览，不能称已有可点击片段或浏览器验证通过。后续片段即使技术检查通过，也只是待用户选择，不能自行标为视觉已接受。

## E：宣传与源码不一致

接下来三项具体动作：

1. 保留原生记账、电脑同步、CSV 已通过的限定结论，另列自动采集状态。记录 README“离线 OCR”与指定 revision 在视觉模型未配置时跳过截图入口的冲突；该源码事实不能被宣传覆盖，也不能推断所有版本均如此。
2. 明确待核对的版本链和运行边界：手机实际安装版本、与指定 revision 的对应关系、截图触发入口、离线 OCR 是否存在于该构建，以及视觉模型是否为必要条件。当前无可操作真机，不能把未知版本的已安装应用当作自动采集成功证据。
3. 制定限定验证：在明确版本和实际手机环境中，从截图输入验证触发、识别、入账、同步及未配置模型时的失败行为；未授权外部模型调用，不通过接入外部模型来绕过未知项。若现有权限和环境无法完成，则交付冲突及未验证项，保留候选判断，不编造成功或擅自改走自建路线。

是否开始产品代码修改：**不能据此宣布产品满足自动采集，也暂不开始首页改造。** 当前授权重点是继续验证候选；首页改造不解决自动采集证据缺失。原生记账和同步通过不等于截图触发、识别和自动入账通过；版本、能力与调用约束尚未厘清，不能据此锁定正式改造路线。

当前能交付：已有能力验证记录的范围说明、宣传与指定源码行为的冲突记录、版本核对清单及自动采集验收步骤。自动采集本轮为 `not-run`，真机验证条件受阻，外部模型调用没有授权；不能交付自动采集满足需求或整体产品已验收的结论。
