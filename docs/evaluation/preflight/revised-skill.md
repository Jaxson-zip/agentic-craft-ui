# 开工决策答复

本次只交付 A/B/C 的拟执行决策，不实现、不联网、不安装、不运行候选或测试、不控制浏览器。以下既有工程结果均为场景提供的事实，不是本轮复测结果。

## A：新 SaaS，赶工与未知复用路线

### 下一步动作（按依赖排序）

1. 将十五分钟交付限定为可供同事审阅的下一步方案与比较计划。沿用已确认的产品/研发团队、项目/迭代/任务范围，以及“两版明显不同的视觉与交互预览”“两种动效节奏看后决定”；不重复询问这两项，也不把它们误记为已选定某个方向。
2. 拟先核对项目规则、实验范围、清单与锁文件、运行脚本和已有测试覆盖，区分可复用的任务行为、交互状态、测试素材，以及尚未形成生产依据的本地身份、worker 和 SQLite 边界。14 项通过只支持已有覆盖路径，不能决定新 SaaS 底座。
3. 先用所给资料形成分层路线表，供用户作出后续选择；此表只算资料比较，候选均未运行：

   | 路线 | 当前可支持的判断 | 决定前仍需核对 |
   | --- | --- | --- |
   | 完整产品二开：Plane | 与项目、迭代协作领域接近，可优先评估直接定制 | 目标功能位于社区还是商业版本；许可、架构、部署、品牌定制、裁剪与升级是否适合目标用途 |
   | 自有产品借底座：Next.js SaaS Starter | 提供登录、团队、计费、后台基础能力 | 是否接受其技术栈；哪些基础模块需要，哪些应裁剪；完整项目协作业务仍需实现 |
   | 自有产品借模块：Better Auth 组织插件等 | 可评估组织、成员、邀请、访问控制模块 | 实际栈适配、身份生命周期、组织与业务租户的映射；业务查询、写入与后台任务隔离仍由应用落实 |
   | 现有实验沿用 | 可作为交互和行为实验的材料 | 不能仅因“已有且测试通过”就让手写身份或 worker 成为生产基础设施；保留它们需要明确适配依据或限定实验目的 |

   UI 组件和动画库另属表现/交互设施，不与整套产品按功能总量排名；它们不提供项目业务，也不决定艺术方向。现阶段建议并列保留完整产品二开与自有产品借底座/模块两条路线，先解决用途约束，再锁定。没有证据据此宣称某一路线已经获胜。
4. 提出下列必要问题。答案到达后才拟锁定底座、部署和生产身份/任务设施；未回答不算认可默认方案。
5. 与路线澄清独立推进两版比较片段的计划：拟让同一份项目/迭代/任务内容和一条“进入迭代 → 选择任务 → 改变任务状态”的操作路径，在两种构图和交互表达下可比较。例如，一版采用精密工作台的紧凑分栏、清晰字阶和任务关联；另一版围绕迭代进度组织更鲜明的排版与对象转换。这里只是待展示的方向假设，不能宣称用户已选择。两种节奏可分别为即时、短促反馈和有连续对象关系的从容编排，拟用同一关键动作比较，说明触发、起止、连续操作、中断与 reduced-motion 降级；不会只换颜色或拿静态截图证明节奏。
6. 路线与视觉分别选定后，才拟扩展成品、接真实契约，并选择跨身份、组织、业务持久化及适用后台副作用的纵向闭环。租户隔离、授权、版本冲突、审计事务和恢复验证应随采用的边界建立，不能让组织插件或四张图替代实测。

### 必要问题

- 是否愿意接受成熟协作产品的业务语义、架构与升级方式来二开，还是必须建立自有产品并只借用通用底座/模块？先用上述能力差异解释取舍，不要求用户猜库名。
- 首批使用是内部团队还是对外客户？是否必须自托管、私有部署或满足特定数据位置要求？是否存在团队已能维护的技术栈或禁止采用的栈？这些答案共同约束技术与部署选择。
- 商业使用、对外开源或内部专用的目标是什么？是否可接受商业版本/托管费用及相关许可条件？只问会排除路线的预算与分发边界。

### 可继续的独立工作

拟整理已确认/待定决策、所给候选能力与未查证项、实验复用边界和验证清单；拟准备两版与两种节奏的同内容比较规格。正常实施授权下，路线未知不应阻碍有限比较片段；本次评估明确禁止创建应用，因此只交付计划，不声称预览已做出。

### 暂不做的事

不联网补造候选维护、版本或许可结论；不安装依赖、复制候选代码、锁定技术栈或整套底座；不扩大手写身份与通用 worker；不提前把任一视觉方向做成整套 SaaS。十五分钟截止不将实验、mock 或有限测试升级为生产验收。

### 可交付状态

本次可交付的是路线差异、必要决策、有限预览规格与下一步验证边界。候选运行、预览制作、两种动态体验、真实集成、租户隔离及生产验证均为 `not-run`；需要用户选择的路线与方向保持待定。既有 14 项通过只按场景事实注明其限定覆盖。本次决策答复可以完成；视觉比较、视觉选择、产品实现和生产就绪均不能称完成。

## B：已有应用，小范围功能且离线

### 下一步动作（按依赖排序）

1. 拟按 Brownfield 小范围功能推进，核对项目规则、当前改动、已有 Vue/FastAPI 脚本、共享表格、选择状态、批量路由、单任务归档服务、权限中间件及相关测试。沿消费者、业务服务和数据库事务读到影响边界，不以固定文件数量截断调查。
2. 拟核对 `POST /tasks/batch-archive` 的真实输入、任务标识与版本、输出、错误及批量原子性/部分失败规则。优先从已明确的归档语义和现有约定提取，不重新发问或擅自决定。前端选择范围与服务端作用范围必须一致。
3. 拟在现有路由和业务层复用单任务服务、权限检查、版本冲突与审计事务，明确批量操作的事务归属，避免逐条调用意外改变既有批量语义。沿现有列表和共享表格增加批量入口、提交状态及结果呈现，使用既有设计系统；身份仍由现有 OIDC 提供。
4. 拟保留提交中选择及失败后的可恢复信息，仅在真实归档结果确认后更新列表与选择状态。409 时提供核对最新数据的路径，不仅替换版本号重交旧数据；超时结果未知时按现有查询/操作标识核对，不盲目重发写入。
5. 拟使用本地已有测试工具验证契约、正常批量归档、既有选择语义、越权任务、版本冲突、事务回滚和审计一致性，以及现有约定所要求的重复提交/部分失败路径。若系统有租户边界，验证批量归档同样约束租户和资源，拒绝时没有越权写入或审计副作用。拟跑适用的已有 lint、类型检查与构建，再在本地服务和浏览器可用时实际走界面主路径。三十分钟内优先保证这一纵向闭环，按实际执行结果交接。

### 必要问题

目前无必须向用户追加的问题：栈、架构约束、角色和归档语义已明确。仓库能回答的选择、事务和响应形态先查仓库。仅当实际规范缺失或互相矛盾、无法判断批量原子性或部分失败含义时，才针对那个具体缺口提问；不重问身份提供方、框架或风格。

### 可继续的独立工作

拟离线核对现有实现、契约、复用点和受影响回归；若局部规格有缺口，仍可完成不依赖该缺口的界面状态和验证计划。不能因无法全网搜索就停工，也不能宣称生态中没有合适工具。

### 暂不做的事

不联网、不安装、不换栈、不替换 OIDC、不重建权限/表格/任务基础设施，不为局部功能新增完整原型或全产品架构图。归档字段变化不触发身份提供方改造。本次只做决策，实际代码、测试、构建和浏览器操作均不执行。

### 可交付状态

本次交付拟实施顺序、复用清单和验证边界，所有新增验证均为 `not-run`。后续只有真实接口、数据库状态、授权与事务结果以及受影响 UI 路径有相应证据，才能称批量归档在已覆盖范围完成。离线并不自动阻断本地验证；若实际缺少运行环境，则具体检查标为 `blocked`。浏览器未运行时必须写 `not-run`，不能推断交互、键盘、窄屏已通过；HTTP 可达或构建成功也不等于业务完成。
