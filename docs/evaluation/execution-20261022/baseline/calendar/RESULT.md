# 日期筛选修复结果

已沿现有 Python 接口 `for_day(rows, selected_day)` 完成修改；没有安装依赖、联网、调用外部服务或提交 Git。

## 复现与根因

修复前实际运行 `python checks.py`，退出码 1，原有 3 项检查全部失败。原始输出保存在 `BASELINE.txt`。

函数原先直接比较时间字符串前 10 个字符，比较的是存储日期而非 UTC+08:00 的界面日期。例如选中 `2026-10-21` 时，正确 UTC 区间应为 `[2026-10-20T16:00:00Z, 2026-10-21T16:00:00Z)`；旧实现得到 ID `[2, 3]`，期望 `[1, 2]`，因此既漏入账也混入次日账单。

## 修改

- `ledger.py`：解析 ISO 时间及其偏移，使用 UTC+08:00 本地零点开始、次日零点结束的半开区间比较；保留输入顺序和原始行对象。无偏移时间按题目给定的 UTC 存储约定解释。
- `checks.py`：保留原有 3 项检查，增加跨年、微秒边界、原始对象与值保持、无偏移 UTC 时间回归检查。
- `BASELINE.txt`：修复前原有检查失败证据。
- `REGRESSION.txt`：修改后完整回归输出。
- `RESULT.md`：本结果说明。
