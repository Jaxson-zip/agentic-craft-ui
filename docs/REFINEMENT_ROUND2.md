# 第二轮完善与验证

日期：2026-10-12。修订基线：Gemini 更新 `49b427f`。环境：Windows / Codex Desktop，Python 3.13.9，Node.js 24.15.0，本地 Chromium。旧验证文档保留其原基线；本记录描述这次修改。

## 完善范围

- 将全网开源搜索与固定风格确认改为条件路径，保留新产品的复用评估；尊重已授权自主推进、已有组件和离线环境。
- 保留清透浅色与冷黑深色作为可选方向；布局由任务推导，移除没有来源的获奖保证、固定骨架与对品牌暖色的普遍禁令。
- 将颜色示例变成实际 `assets/themes.css`，补齐按钮前景与焦点变量；提供同源 CSS 的无依赖本地预览。
- 恢复适用状态与阶段证据，增加表单枚举一致性、409 草稿恢复及超时结果未知的规则；不要求视觉任务创造新协议。
- 明确浏览器缺失、截图、模拟数据、build 与真实持久化各自的证据边界。
- 实战页面只修复本轮发现的回归：无效类别、按钮换行/裁切、手机关闭热区、辅助与状态文字、减少动态偏好以及七天指标文案。

## 先失败，再修复

提取基线 CSS 为复现资源，先运行新增配色检查。按旧深色 rgba 在卡片上合成后计算，辅助文字的八个表面配对、浅色三类状态及深色中性状态共 12 个数值断言失败；`--on-brand` 与 `--focus-ring` 在基线缺失，新增消费契约另有 12 个缺键错误。缺键错误描述新资源契约，不将它们计为十二个已存在产品故障。新版全部指定配对通过。7:1 是增强目标；普通文字 AA 的 4.5:1 不能四舍五入后算达标。

对订阅实例真实 HTML 选项与领域校验新增一项回归，先因多出的“开发工具”失败，移除此未经 API 支持的枚举后通过。没有扩大业务分类或修改后端状态机。

## 实际产品迁移验证

独立 Agent 在隔离目录制作暖色诗刊阅读原型，执行过程末尾因额度限制未返回正常完成摘要；本地文件和检查记录已生成。主 Agent 重新执行 `node --check app.js`、5 项领域/真实事件接线测试及静态/配色计算，全数通过，并接手实际浏览器验证。

浏览器实际选长标题文章，Space 添加书签、Enter 移除，书签视图显示空态；手机目录展开/选文后收起，按钮有可见焦点。一次书签为 1 后刷新重置为 0。320、360、390、819、820、821、1440px 无横向页面溢出，书签按钮44px；控制台无 error/warn。桌面与手机截图及宽度记录在 evidence/round2。原型使用原始示例写作，无真实账户、持久化或 API。未做200%缩放和完整辅助技术检查。

它用于检验规则能否迁移到其他产品，不是与无 skill 的性能对照。测试原型留在隔离评估目录，不作为默认项目骨架装入 skill。

## 限制

目前只在 Windows / Codex 中运行；跨平台依据无平台绑定的资源结构与标准库实现，没有执行 macOS/Linux 或其他模型宿主矩阵。未完成全套 WCAG 合规审计、公网发布、负载测试。配色测试仅覆盖发货的指定配对；应用自定义叠色、禁用态、字体与复杂组件仍须实测。真实 HTTP/SQLite 由自动测试覆盖，本轮浏览器写入使用模拟模式，不把它报告为新的真实 UI/API 保存测试。

订阅实例仍未模拟“创建已提交但响应丢失”，未实现创建幂等键；本轮不借视觉修复扩展该业务机制，已将相应恢复规则和具体未验证边界写清。
